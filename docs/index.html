ThermoGuard
Server Cabinet Overheat Guard

A Java Swing desktop app that watches the air inside an equipment cabinet over USB Serial and reacts to overheating on its own: it opens a vent flap, switches on a cooling fan through a relay, shows the status on a light and sounds an alarm.

01

Overview

A server or network cabinet traps heat, and when the air inside gets too hot the equipment throttles or fails. ThermoGuard measures that air and reacts without a person: above the limit the vent flap opens and the cooling fan starts; when it cools the vent closes and the fan stops.

The Arduino reads the DHT sensor every second and streams the values to the Java app. In AUTO mode the Arduino decides by itself: above the temperature or humidity limit it opens the servo vent, switches the fan on through the relay, turns the LED red and beeps. In MANUAL mode the user drives the vent, fan, LED and buzzer from the GUI.

The prototype was built and tested in Wokwi first, then run on a real Arduino UNO from the lab.

The relay sits in the fan's own supply wire, so the fan's current never passes through an Arduino pin — the board only tells the relay "on" or "off". In Wokwi the fan is modelled by an LED switched through the relay, because Wokwi has no DC motor part. The lab's L9110 Fan Motor Control Module (KS0168) is the alternative driver.

The three LED channels each run through a 220 Ω resistor to limit current. The servo, sensor and relay coil share 5V and GND with the board. The fan hangs off the relay's normally-open contact, not off a pin. The full Wokwi circuit is in arduino/diagram.json.

05

Serial Protocol

USB Serial, 9600 baud, 8N1, ASCII. One message = one line ending with \n. Fields separated by ;, values as key=value. Every command gets a reply.

DirMessageMeaning
A→JHELLO;ThermoGuard;v2.0Board ready
A→JDATA;T=24.5;H=52.0;WIN=0;FAN=0;MODE=AUTO;ALARM=0Telemetry every RATE ms
A→JACK;<cmd> · ERR;<code>Reply to a command
J→APING → PONGHealth check (watchdog)
J→AMODE AUTO | MODE MANUALWho controls actuators
J→AWIN OPEN | WIN CLOSE | WIN 0–180Servo vent (manual)
J→AFAN ON | FAN OFFCooling fan (manual)
J→ALED r g bRGB 0–255 (manual)
J→ABUZZ ON | BUZZ OFFBuzzer
J→ATHR T 28 · THR H 70Alarm limits
J→ARATE 200–10000Telemetry interval (ms)

Example session:

< HELLO;ThermoGuard;v2.0
< DATA;T=24.3;H=51.0;WIN=0;FAN=0;MODE=AUTO;ALARM=0
> MODE MANUAL
< ACK;MODE MANUAL
> FAN ON
< ACK;FAN ON
< DATA;T=29.1;H=48.0;WIN=90;FAN=1;MODE=MANUAL;ALARM=1
> FAN ON
< ERR;FAN_IN_AUTO

Error codes: UNKNOWN_CMD, BAD_ANGLE, BAD_LED, BAD_RATE, BAD_LIMIT, WIN_IN_AUTO, LED_IN_AUTO, FAN_IN_AUTO, SENSOR_READ.

Hysteresis on the fan. The fan starts when the temperature crosses the limit but stops only 1.5 °C below it. Without that gap the relay would click on and off every second while the temperature sits exactly on the limit, which is both noisy and hard on the relay.

07

Results

  • Live temperature and humidity in the GUI every second, with a chart of the last 60 readings.
  • AUTO: above 28 °C the vent opens, the fan starts, the LED turns red and the buzzer beeps; it returns to green when it cools.
  • The fan keeps running until the temperature falls 1.5 °C below the limit, then stops — the hysteresis is visible in the log.
  • MANUAL: the slider moves the servo vent, Fan on / Fan off switch the relay, buttons set LED colour and buzzer; every command is acknowledged.
  • Wrong port, unplugged cable, silent board and invalid commands produce clear messages; the app reconnects automatically.
  • Demo mode runs the whole scenario in under 25 seconds.
08

Reflection

Difficult: reading serial data without freezing the GUI — solved with a background thread and SwingUtilities.invokeLater. Keeping the Arduino responsive while beeping — solved by replacing delay() with millis() timing. Making the fan behave sensibly near the limit — solved with hysteresis instead of a plain threshold.

Learned: designing the protocol first made both sides testable separately (Wokwi Serial Monitor for Arduino, the log panel for Java). A relay is not just an extra output: it changes how you think about where the current comes from.

Next: an LCD on the cabinet itself, a history viewer for the CSV file, and a second sensor so one reading can be compared with the room.
